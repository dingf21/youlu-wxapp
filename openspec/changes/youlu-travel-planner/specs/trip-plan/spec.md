# Spec Delta

## Purpose

管理用户的旅程计划生命周期：创建、编辑、列表浏览，以及按日编排行程日程，作为出行规划的核心实体。

## ADDED Requirements

### Requirement: 创建旅程计划
系统 MUST 允许用户创建一条旅程计划，至少包含名称、出发日期与结束日期；结束日期不得早于出发日期。

#### Scenario: 成功创建
- **WHEN** 用户提交有效的名称、出发日期与结束日期
- **THEN** 系统保存该旅程并使其出现在旅程列表中

#### Scenario: 日期无效
- **WHEN** 用户提交的结束日期早于出发日期
- **THEN** 系统拒绝保存并提示日期无效

### Requirement: 浏览旅程列表
系统 MUST 展示用户已保存的旅程列表，每条至少显示名称与日期范围。

#### Scenario: 有旅程时
- **WHEN** 用户打开旅程列表且至少存在一条旅程
- **THEN** 系统按可识别顺序展示全部旅程的名称与日期范围

#### Scenario: 无旅程时
- **WHEN** 用户打开旅程列表且尚无旅程
- **THEN** 系统展示空状态并提供创建入口

### Requirement: 查看与编辑旅程
系统 MUST 允许用户打开旅程详情查看基础信息，并编辑名称与日期范围；变更 MUST 持久化。

#### Scenario: 编辑后保存
- **WHEN** 用户在详情中修改名称或日期并确认保存
- **THEN** 系统更新该旅程，列表与详情均反映新值

### Requirement: 按日编排行程
系统 MUST 按旅程日期范围内的每一天提供日程视图，并允许用户为某一天添加、调整顺序或删除日程条目。

#### Scenario: 为某日添加日程
- **WHEN** 用户在指定日期添加一条日程条目
- **THEN** 该条目出现在该日日程中并可被再次查看

#### Scenario: 调整日程顺序
- **WHEN** 用户调整同一天内两条及以上日程条目的顺序
- **THEN** 系统保存新顺序并在该日视图中按新顺序展示

### Requirement: 删除旅程
系统 MUST 允许用户删除整条旅程；删除后该旅程及其关联日程不再出现在列表与详情中。

#### Scenario: 确认删除
- **WHEN** 用户确认删除某条旅程
- **THEN** 系统移除该旅程，列表中不再显示该条目
